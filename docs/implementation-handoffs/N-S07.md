### Business semantics

Nothing was invented. The bodies are the source v053 bodies. Three deliberate
provider-neutral changes, all recorded per function in the inventory:

- `is_active_team_member()` and `is_app_admin()` resolved the signed-in
  principal through a provider claim helper. They now resolve the
  transaction-local canonical actor and require an active canonical user **and**
  an active membership, which is exactly the S06 policy contract.
- `admin_update_team_member` counted admins linked to the provider identity
  column. It now counts the canonical `team_members.user_id` link, which S06
  made `NOT NULL`.

S07 hardening deltas that change no business result: every function pins a fixed
`search_path`, including the five source functions that had none, and the AI
guard performs an explicit single-statement check instead of relying on a later
parse failure.

### Milestone contract

`leads_keep_milestones` is unchanged. A NULL milestone may be filled forward; a
non-NULL milestone is silently restored rather than nulled; a repeated sync
upsert changes nothing. The only sanctioned regress remains
`delete_manual_message`'s transaction-local `app.allow_milestone_regress`
recompute, and the flag is gone again in the next transaction. All five columns
(`invited_at`, `connected_at`, `first_message_at`, `replied_at`, `added_at`) are
covered.

### AI SQL guard

Source contract kept: one `SELECT`/`WITH` statement, an inner 1000-row cap, a
`coalesce(jsonb_agg(...), '[]')` result that is never NULL, and a 10 second
statement timeout. Added: a length-preserving, literal- and comment-aware scan
so empty, blank, comment-only, unterminated, multi-statement, mutation, DDL,
session-control, `FOR UPDATE`, `SELECT ... INTO` and escape/unicode-literal input
all fail closed with `22023` before anything is planned. A terminator or keyword
that appears only inside a literal, quoted identifier or comment is correctly not
a statement and is still accepted.

Privilege design, without provider roles:

- `app_ai_runner` replaces `ai_sql_runner`: no login, non-superuser,
  non-`BYPASSRLS`, owns no business object, owns only the guard function, holds
  SELECT-only grants and is the only role with an `_ai_read` policy. It is
  column-scoped on `instances` (no `config`) and `team_members` (no `email`,
  `role` or `user_id`), and has no grant at all on `users`/`user_identities`.
  It receives `CREATE` on `public` solely to take ownership of the guard, and
  the same artifact revokes it.
- `app_system`, the server-owned system/job principal S06 reserved for S15, is
  the only role that may execute the guard. Its entire privilege set is `USAGE`
  on `public` plus `EXECUTE` on that one function — no table, sequence or other
  function privilege. This is a deliberate delta from the S06 note that
  `app_system` has no grants until S15; it gains no ownership and no
  `BYPASSRLS`.
- `app_runtime`, `app_readonly`, `app_migration`, `app_machine`, `PUBLIC` and any
  anonymous principal cannot execute the guard. The browser never reaches the
  database.
- No role has a write path through the guard, and the sandbox cannot execute any
  business function, so a `SELECT` that merely calls a `SECURITY DEFINER`
  function is refused on privileges.

## Known limits

1. **The 10 second limit needs the caller.** PostgreSQL arms `statement_timeout`
   when the outer statement begins, so the value the guard sets on itself cannot
   abort a call already in flight. Measured in the clean-room: a 14 second query
   ran to completion with the guard's own setting, and aborted at 10.1 seconds
   when the caller issued `SET LOCAL statement_timeout = '10s'` first. Both
   halves are pinned as assertions. **S11's transaction wrapper and S15's AI
   handlers must arm the limit per transaction.** This limitation is inherited
   from the source `ai_execute_sql`, not introduced here.
2. **`SECURITY DEFINER` RPCs run with owner rights.** `admin_update_team_member`,
   `apply_follow_up_action`, `delete_manual_message` and `pipeline_auto_advance`
   are `SECURITY DEFINER` exactly as in the source, so once invoked they bypass
   RLS. They are gated by `EXECUTE` grants and by the server-owned API, which
   must authorize the caller before invoking them. S15 owns that handler
   authorization; S07 deliberately did not invent in-function actor checks the
   source never had.
3. **Result-shape quirk carried over.** The source wrapper aliases its subqueries
   `sub` and `t`; a submitted query with a column of the same name shadows the
   alias and yields an array of scalars instead of objects. Preserved unchanged
   rather than silently altering the AI result contract.
4. **pgcrypto is `PUBLIC`-executable.** S05 installs pgcrypto into `public` and
   its functions keep the extension default, so generated SQL can call them. They
   read no application data. Every S07 catalog assertion excludes extension
   members from the portable function inventory.
5. **Mutation keyword rejection is lexical.** The keyword list is checked against
   code outside literals, identifiers and comments. It is a defence-in-depth
   layer on top of the SELECT-only role, not a substitute for it; it also rejects
   a few harmless-but-unused spellings such as `SELECT ... FETCH FIRST`-adjacent
   session keywords if they ever appear as bare words.
6. **The AI read policies use `USING (true)`.** This matches the source: the AI
   path is server-owned and aggregate, and reach is bounded by SELECT-only and
   column-scoped grants rather than by an actor. It is not an actor-scoped path
   and must not be exposed to a browser.
7. `app_ai_client` exists only in the clean-room bootstrap so the assertions can
   reach `SET ROLE app_system` from a real login. It is never part of the
   artifact or the production role contract.
