## Scope completed

adapter wrappers, canonical runtime wiring, fake bundle naming, and
resume-safe provider request IDs. S26 was not started.

- Added `NeonOperationsApi`, `IdentityOperationsApi`,
  `ObjectStorageOperationsApi`, and `HostingOperationsApi` as narrow named
  capability seams. They accept named operations only; no arbitrary URL, HTTP
  payload, SQL, shell command, environment map, or secret read crosses them.
- Added `NeonDataAdapter`, `IdentityOperationsAdapter`, and
  `R2ObjectStorageAdapter`. Results are strict-schema parsed and redacted;
  canonical requests are checked for secret material before delegation.
- Kept old Supabase/Auth port names only as deprecated compatibility types and
  left the legacy SDK implementation behind the canonical `P4CSdkPorts` fields
  (`data`, `objectStorage`, `identity`, `hosting`, `email`, `domain`, and
  `sourceRepository`). Runtime assembly now uses the canonical adapter classes.
- Added canonical fake classes and made `FakeOnboardingProviderBundle` expose
  only the capability vocabulary used by the core.
- When a provider reports `outcome_unknown`, the executor now persists the
  redacted `provider_request_id` on the outcome-unknown step. Retry remains
  deterministic and uses the existing provider fake's adoption/idempotency
  behavior.
