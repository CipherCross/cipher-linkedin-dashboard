## S26 preflight unblocked — three latent defects — 2026-08-11

### The four blockers, per owner decision

The workspace is self-use and stays on Vercel Hobby; EU R2 jurisdiction, a
pinned `fra1` region, and a signed agent release manifest are not required for a
disposable, non-production drill. `blocking_conditions` is now empty,

### Defect 1 — the CLI planned S26 on P4-C inputs

`cli.ts` called `p4cBusinessInputs()` for **both** runtimes. In `--s26` mode that
supplied tenant slug `p4c-lab` against an allowed slug of `s26-disposable-lab`,
plus Supabase-era catalog ids (`supabase-pro`, `eu-west-1`,
`p4c-reviewed-processors`). No plan could ever have validated. The S26 profile
now carries a closed `selections` block and `s26BusinessInputs()` derives the
inputs from it, reading `pricing_catalog_id` off the pinned pricing snapshot so
the pair the validator compares cannot drift.

### Defect 2 — bridge routes were sent to provider API hosts

Neon, R2 and Vercel each expose a mixture of direct provider routes and bridge
routes, but `createS26ConcreteApiBundle` gave each client a single transport —
the direct one. Every `inspect` therefore posted
`/s26/control-plane/v1/.../inspect` to `console.neon.tech` or `api.vercel.com`
carrying that provider's token, and the provider answered an opaque 401. The
three mixed clients now take both transports. The existing test compared only
pathnames, which is why it passed; it now compares full origins, and a new test
pins that data and hosting inspections travel on the bridge.

### Defect 3 — inspections failed their own canonical schema

The transport adds `providerRequestId` to every response so an ambiguous
mutation stays resumable. Read-only inspections have no such field in their
canonical shape, and the adapter validates them with a strict schema, so the
added key was rejected. The six inspections now drop it.

### Two credential-installation mistakes

The secret store keeps values as `v1_<base64url>`. The Worker's
`BRIDGE_BEARER_SECRET`, `NEON_API_TOKEN` and `VERCEL_API_TOKEN` had been
installed as the raw envelope that `security ... -w` prints rather than the
secret inside it. The bridge bearer was aligned locally so `SecretStore.get()`
returns the value the Worker holds; the Neon and Vercel Worker secrets were
re-installed with their decoded values. No value was printed or logged.

An earlier reading of this session that the provider tokens were placeholders
was wrong: tested in decoded form, Neon and Vercel both answer 200. The
Cloudflare/R2 token remains invalid even decoded (401 on token verify); it is
not used by preflight but is required at apply.

### Defect 4 — domain inspection rejected the pre-provisioning state

`#domainInspect` treated Vercel's 404 from `/v6/domains/{host}/config` as a
provider error. A hostname no project has claimed yet has no config by
definition — that is exactly the healthy state for a new tenant. It is now
handled the same way `#hostingInspect` already handled a missing project.
