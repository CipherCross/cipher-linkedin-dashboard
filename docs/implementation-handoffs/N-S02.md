## Final G0 decisions

| Decision | Accepted value |
|---|---|
| Neon | Free, AWS Europe (Frankfurt), one project per tenant |
| Recovery | RPO ≤24 hours; RTO ≤8 business hours; maintenance window ≤90 minutes |
| Auth | Self-hosted Better Auth behind `IdentityProvider`; no managed Auth service |
| Storage | Cloudflare R2 Standard, private bucket per tenant; separate scoped agent-artifact bucket |
| Hosting | Vercel remains the temporary `HostingControlPlanePort` adapter |
| Production maturity | GA-only; Neon Data API, managed Neon Auth and Neon Storage are excluded |

The source baseline remains PostgreSQL 17.6, 29,224,083-byte database, 602
objects / 18,359,103 bytes, four users and two initial tenants. The default
migration remains `pg_dump`/`pg_restore`; logical replication is fallback only.

## Rejected alternatives

- Neon Launch/Scale now: no measured capacity or recovery reason for paid tier.
- Managed Neon Auth, Neon Storage and Data API: excluded by GA-only and
  provider-neutral boundaries.
- Keycloak now: an extra self-operated service is disproportionate for four
  users; it remains an `IdentityProvider` alternative.
- AWS S3 now: technically compatible but not preferred over R2 at current size
  and requirements.
- Storing bytes in PostgreSQL or running a hosting migration during cutover.
